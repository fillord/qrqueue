## 5. Реализованные функции

### Очередь и талон

- QR-талон с живым короткоживущим подписанным токеном.
- Один QR общего экрана может предлагать несколько назначенных очередей.
- Геозона очереди, расписание и дневной лимит проверяются сервером.
- Один активный талон на очередь или на организацию, в зависимости от настройки.
- Статусы: ожидание, вызов, подтверждение, обслуживание, обслужен, неявка, ушёл, переведён.
- Возврат пропущенного посетителя, перевод в другую очередь, оценка обслуживания.
- Реальное время через WebSocket и Redis pub/sub.
- Web Push предусмотрен, если на production заданы VAPID-ключи.
- Примерное время ожидания учитывает работающие кабинеты.

### Кабинеты и сотрудники

- Один кабинет может иметь свою очередь или использовать существующую.
- Несколько кабинетов могут обслуживать одну общую очередь.
- Операторы назначаются на кабинеты.
- CRUD построен через архивирование: история не удаляется.
- Поиск, фильтры, сортировка, включение/отключение, восстановление из архива.
- Email обычного сотрудника меняет администратор организации.
- Email администратора организации меняет только суперадминистратор.

### ТВ

- Отдельные режимы: очередь, недельное расписание, YouTube/объявления.
- Для общего табло выбираются очереди и кабинеты.
- Один QR общего экрана предлагает посетителю назначенные очереди.
- На табло показываются текущие, последний и предпоследний вызовы.
- Новый вызов выделяется примерно на четыре секунды.
- Название ТВ редактируется.
- Есть статус online/offline по heartbeat.
- Предпросмотр скрыт внутри раскрытых настроек.
- Есть отвязка и удаление ТВ.
- Озвучка зависит от браузера/устройства; фактическая стабильность на всех ТВ не гарантирована.

### Расписание и медиа

- Отделения создаются заранее.
- Строка врача: отделение, врач, специализация, кабинет, Пн–Вс.
- Excel-шаблон и атомарный импорт.
- Все семь дней видны одновременно.
- Строки врачей компактно делятся на страницы; отделения переключаются последовательно.
- Для каждого ТВ расписания выбираются нужные отделения.
- Видео переведено на YouTube-видео и YouTube-плейлисты.
- Плейлист повторяется, player DOM сохраняется между переходами.
- Звук и autoplay зависят от политики браузера ТВ и первого взаимодействия.
- Старый механизм загрузки видео частями остался в коде/схеме, но основной пользовательский сценарий — YouTube.

### Учёт рабочего времени — пилот

- Отдельные сотрудники, включая врачей без аккаунта очереди.
- Привязка к заранее созданному отделению.
- CRUD и Excel-импорт с проверкой отделения.
- Четырёхзначный личный код.
- Статичный QR только для регистрации лица.
- Заявка на лицо подтверждается администратором после личной сверки.
- Стойка регистратуры привязывается шестизначным кодом.
- На стойке сотрудник нажимает пробел и проходит распознавание лица.
- На телефоне используются QR, личный код, лицо и при включении геопозиция.
- Приход и уход чередуются по последней отметке.
- Администратор добавляет и исправляет отметки с обязательной причиной.
- Есть сводка по отделениям.
- Проверка живости/движения отключена; это обычная сверка лица.
- Смены, табели и автоматический расчёт опозданий пока не реализованы.

### Профиль и безопасность

- Изменение имени, фото и пароля.
- Смена пароля отзывает другие сессии.
- TOTP обязателен для `superadmin` и `org_admin`.
- Сброс TOTP суперадмина выполняется только серверным скриптом после проверки пароля.
- Rate limiting для входа, сканирования, привязки ТВ, заявок и ИИ.
- Доступ к чужой организации маскируется как 404.
- Секреты хранятся только в `.env`/`.tunnel.env`, не в frontend.

### ИИ-помощник «Навигатор»

- Можно полностью отключить в профиле.
- Облачные ответы ИИ можно выключить отдельно, оставив встроенные подсказки.
- Gemini API вызывается только backend; ключ не передаётся браузеру.
- Модели отправляются текст вопроса, роль, текущий маршрут и статическая карта функций; данные пациентов, талонов и фотографии автоматически не подставляются.
- Карта включает маршруты, точные действия и правила заполнения основных форм для каждой роли.
- Gemini возвращает структурированный `action_id`.
- Frontend по `action_id` открывает правильный раздел и подсвечивает элемент.
- Действие чужой роли отбрасывается backend.
- Подсказки не выходят за экран, пропускают клик по выделенному элементу и продолжаются после перехода.
- При самостоятельном переходе в другой раздел появляется новая контекстная подсказка.

## 10. Безопасное обновление production

1. Сделать проверенный backup.
2. Запустить frontend и backend проверки.
3. Применить изменения исходников на сервере.
4. Собрать образы.
5. Применить Alembic до запуска нового backend, если есть миграции.
6. Перезапустить только нужные сервисы.
7. Проверить `/api/health`, `/login`, WebSocket, ТВ и один реальный QR-сценарий.

Команды на Oracle после доставки полного исходного дерева:


## 12. Известные ограничения и риски

- GitHub отстаёт на 16 коммитов с учётом этого отчёта. Новый чат, который клонирует GitHub сейчас, не получит ИИ-помощника, последние исправления и handoff-файл.
- Полный backend regression suite после всех новых функций не запускался.
- Проверка живости лица отключена; фото или видео теоретически могут обмануть распознавание.
- Чек-ин пока не рассчитывает смены, опоздания и табель.
- Озвучка ТВ зависит от браузера и установленных голосов; ранее на реальном устройстве была нестабильна.
- YouTube звук/autoplay может требовать первое действие пользователя на ТВ.
- Бесплатный Gemini имеет лимиты и внешнюю политику обработки данных.
- Oracle Always Free VM может быть изъята при длительном простое; swap отсутствует.
- Внешний off-site backup в Google Drive в этом срезе не подтверждён.
- Доставка Web Push на реальных телефонах и наличие production VAPID-ключей требуют отдельной проверки.
- Полная ручная приёмка всех ролей, мобильных браузеров и разных моделей ТВ не завершена.
- Frontend bundle около 775 КБ до gzip; Vite предупреждает о chunk больше 500 КБ. Работает, но позже стоит сделать code splitting.
- `PROJECT_STATUS.md` обновлялся 28 сентября и частично устарел. Этот документ новее.
