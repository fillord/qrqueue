# Состояние проекта

Обновлено: 2 октября 2026.

Проверенная исходная точка перед текущей доработкой: `9ee2455167809af28e04381ce80f933139cab8d5`; локальный `main`, GitHub и Oracle совпадали. Текущая локальная проверка: полный backend suite — 196 тестов; frontend — 84 теста и production build. Для выпусков добавлены идентификация Git SHA в Docker-образах и `/api/health`, единый безопасный Oracle-deploy и системная проверка свежести verified backup.

Основные функции MVP реализованы. Публичный `https://queue.omni-book.site` работает на Oracle VM через отдельный Cloudflare Tunnel; исходный код хранится в `fillord/qrqueue`. После исправления плейлиста frontend развёрнут на Oracle, а пользователь подтвердил на реальном телевизоре работу режима «Повторять все». Полная приёмка остальных сценариев на целевых устройствах ещё не завершена.

## Завершено

- Талоны: транзакционные переходы, конкурентные вызовы, атомарный перевод, порядок возвращённых посетителей, позиция в очереди, подтверждение присутствия, оценки и аудит.
- QR: обновление по времени сервера, перекрытие сроков, очистка просроченного кода. Потеря сети не снимает привязку ТВ.
- Табло: все вызовы одной очереди с кабинетами, включая подтверждённые и обслуживаемые талоны; повторный вызов учитывается по идентификатору талона и счётчику вызовов. На общем табло можно показывать все очереди или выбрать несколько конкретных, а вызовы ограничить выбранными кабинетами. Общий экран показывает один живой QR: посетитель сканирует его, выбирает очередь из назначенных и получает талон по тем же правилам расписания, геозоны и активного талона. Экран одной очереди сохраняет прямой QR. Язык и выбор очередей/кабинетов изменяются через админку.
- ТВ-расписание: отдельный экран показывает недельную таблицу каждого отделения — одна строка на врача и все семь столбцов Пн–Вс одновременно, включая узкие экраны. Для каждого ТВ можно выбрать показываемые отделения, оставив служебные отделения только для учёта сотрудников. При большом списке перелистываются страницы врачей, затем отделения. Другой экран показывает ролики и объявления крупно, оставляя сверху название организации и небольшие дату и время. Для него можно повторять все активные материалы либо отметить выбранные галочками; видео проигрывается целиком, вертикальный кадр дополняется размытой копией по бокам. Между роликами есть короткая пауза для освобождения видеодекодера ТВ; материал с временной ошибкой пробуется снова. Расписание можно заполнить вручную или импортировать из шаблона XLSX с одной строкой на врача. Импорт проверяет все строки до записи и заменяет расписание только отделений из файла. Показ рекламы включается отдельно для каждого медиаэкрана. Видео загружается частями: 50 МБ на файл по умолчанию, 100 МБ после включения суперадминистратором для организации; изображения — до 10 МБ. Браузерный макет подстраивается под разрешение ТВ.
- Заявки: лендинг сохраняет их в PostgreSQL; в кабинете суперадминистратора есть список с постраничной загрузкой и отметкой обработки. Ограничение частоты — 5 заявок в час на IP; изменение статуса аудируется.
- Админка: суперадминистратор создаёт, редактирует, архивирует и восстанавливает организации и их пользователей; администратор организации редактирует свои настройки и управляет сотрудниками, очередями и кабинетами. Архивация скрывает запись и закрывает доступ, но сохраняет историю; восстановление не включает её автоматически. Активные талоны препятствуют архивации; для очереди сначала архивируются кабинеты. В списках есть поиск, фильтры, сортировка и страницы. Назначения операторов сохраняются. Ошибки загрузки основных списков и отчётов показывают повторную загрузку. Рабочие страницы занимают доступную ширину, боковое меню сворачивается с сохранением выбора, на планшете переходит в горизонтальную навигацию. Экраны регистратора и выбора кабинета расширены.
- Администратор видит центр проблем, дневной отчёт и состояние подключённых ТВ. Для новых организаций доступны шаблоны поликлиники и центра обслуживания; настройки ТВ раскрываются отдельно и содержат предпросмотр и отвязку.
- Учёт рабочего времени (пилот): сотрудники распределяются по заранее созданным отделениям; есть CRUD, Excel-импорт, четырёхзначные личные коды, недельный рабочий график, регистрация лица по статичному QR с подтверждением администратором, привязанная стойка с кодом, геоограничение телефона, отметки прихода/ухода и исправления с причиной. Подробный отчёт сопоставляет план и факт, считает опоздания, ранние уходы, переработку, отсутствие и незакрытые смены и выгружается в CSV. Проверка движения лица отключена; остаётся обычная сверка лица.
- Профиль: персонал меняет имя, фото и пароль; почту сотрудников организации меняет её администратор, почту администратора организации — суперадминистратор.
- Проверка входных данных: часовые пояса, непустые имена, ограничения координат и чисел, интервалы расписания, дубликаты дней, длина паролей в байтах, запрет null для обязательных полей PATCH.
- Уведомления: вызов, приближение среди первых трёх без повторов, пропущенный вызов; русский, казахский и английский по языку посетителя. Прогноз ожидания учитывает активные кабинеты; при отсутствии работающих кабинетов прогноз не показывается.
- Расписание: открытие/закрытие по часовому поясу организации, ручная пауза до границы расписания. Пустое расписание явно означает отсутствие ограничений.
- Доступ: обязательная TOTP для административных ролей, защита от повторных кодов, ограничения запросов, отзыв доступа при деактивации. Сброс 2FA отзывает прежние сессии и ожидающие коды; для суперадминистратора добавлена серверная процедура восстановления с проверкой пароля и записью в аудит. Межорганизационная изоляция проверяется тестами.
- События публикуются после фиксации транзакций; WebSocket освобождает подключения БД между снимками. Фильтр аудита использует день в часовом поясе выбранной организации; общий аудит — UTC.
- PWA: manifest, иконка и offline-страница с повтором подключения. Состояние очереди и действия не кэшируются для автономной работы.
- Сборка: зависимости backend зафиксированы; Docker-контекст исключает локальные node_modules/кэши. Добавлены инструкции, скрипт запуска с миграцией до приложения, проверка восстановления бэкапа, GitHub Actions для backend/frontend.
