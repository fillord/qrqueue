## Бэкенд — новое

Два пробела, оба согласованы с пользователем перед правкой:

- **`POST /public/tickets/{id}/rate`** — был заявлен в ARCHITECTURE.md, но не существовал:
  ни роута, ни `services/tickets.py: rate()`, хотя колонки `tickets.rating`/`rating_comment` уже
  были в модели с шага 1 (миграция не потребовалась). Пользователь заранее разрешил добавить, если
  не хватает — сделано без отдельного вопроса. `rate(db, *, ticket, client, rating, comment)`:
  только `status=served` (иначе `409 invalid_transition`, тот же `_require_status`, что и везде),
  только `rating is None` (иначе `409 already_rated`), только свой `client_id` — роут проверяет
  `ticket.client_id != client.id` → `404`, как и `confirm`/`leave`. Без realtime-события — оценка
  не входит в список событий из раздела 5 ARCHITECTURE.md, публиковать нечего. `TicketDetailOut`
  получил поле `rating: int | None`, чтобы `/t/:id` при обычном `GET` тоже знал, ставить форму
  оценки или «спасибо» — не только сразу после отправки.
- **`tv_screens.language` в `GET /tv/state`** — обнаружилось по ходу TTS: язык экрана нигде не
  отдавался самому экрану (только в admin-facing `TVScreenOut`), так что было не на чем строить
  «озвучить на языке экрана». Согласовано отдельно, добавлено просто как ещё одно поле в
  `TVStateOut`/`build_tv_state` — без миграций, поле уже существовало в модели.

Тесты (добавлены): `test_rate_served_ticket_succeeds_and_blocks_second_rating`,
`test_rate_non_served_ticket_returns_409`, `test_rate_by_other_client_is_404`,
`test_tv_state_reflects_screen_language`. Итого backend-сьют — **89 тестов** (было 81).

## Фронтенд

- **TTS** (`hooks/useTvAnnouncer.ts`) — на каждый новый снапшот `/ws/tv` (WS всегда шлёт полное
  состояние, отдельного типа события до табло не долетает — раздел 5 ARCHITECTURE.md этого не
  предусматривает) сравнивает `now_serving` каждой очереди с предыдущим снапшотом; если талон
  реально сменился — озвучивает номер (и кабинет, если есть) через встроенный
  `SpeechSynthesisUtterance`, без зависимостей. Первый снапшot после монтирования только
  запоминает базу для сравнения и никогда не озвучивается — иначе табло вываливало бы очередь
  текущих вызовов при каждой перезагрузке страницы. Язык озвучки — `state.language` (новое поле
  из `/tv/state`), сопоставлен на `ru-RU`/`kk-KZ`/`en-US`; фраза собирается через
  `i18n.getFixedT(state.language)`, то есть в языке экрана, а не в текущем языке интерфейса
  браузера — эти две вещи специально не связаны, менять глобальный язык страницы из-за настройки
  одного экрана было бы лишним. Включение/выключение — `lib/tvAnnouncements.ts`, ключ в
  `localStorage` того браузера, что показывает этот конкретный экран (не в БД, как и просили),
  тумблер — маленькая кнопка в подвале `/tv`, по умолчанию включено.
- **Оценка на `/t/:id`** (`components/RatingForm.tsx`) — при `status === 'served'`: если
  `ticket.rating == null` — 5 звёзд (кнопки, не `<input type="radio">`, с ховер-подсветкой) +
  необязательный комментарий → `POST /rate`; после успешной отправки — «Спасибо за оценку!» без
  повторной формы. Если открыть `/t/:id` уже после оценки (например, обновить страницу) — тоже
  сразу «спасибо», не форма: решает по `rating` из обычного `GET`, не по локальному состоянию
  формы.
- Новые строки — `tv.announce.*`, `ticket.rating.*` — на kk/ru/en.

## Ручной сквозной тест

Проверено вручную прямыми HTTP-запросами теми же payload'ами, что шлют формы/страницы (см. `git
log` этого шага), плюс визуально через `docker compose up`:

1. Создать организацию/админа/оператора, две очереди («Терапевт», «Хирург»), кабинет на первой из
   них, назначить оператора.
2. `/admin/tv-screens` → создать экран **без выбора очереди** («Без очереди (табло зала)»).
   Подключить его на `/tv/pair` кодом. `/tv/state` для этого device_token отдаёт обе очереди
   сразу.
3. Открыть `/tv` — табло зала: список из двух очередей, у каждой название/текущий
   вызов/«Ожидают»/статус. Отсканировать QR очереди «Терапевт» (или через `/q`) → на табло
   счётчик «Ожидают» вырос.
4. Оператором вызвать талон (`/operator/queue`, «Вызвать следующего») — на `/tv` в строке
   «Терапевт» появляется номер талона, и — если включена озвучка (кнопка в подвале экрана) —
   браузер проговаривает номер вслух на языке экрана.
5. Завершить приём (`/operator/queue`, «Начать приём» → «Завершить»). У клиента на `/t/:id`
   появляется форма «Оцените приём» — 5 звёзд.
6. Поставить 5 звёзд, отправить → «Спасибо за оценку!», форма больше не показывается ни сейчас,
   ни при обновлении страницы.
7. Войти **org_admin** → `/admin/analytics` за диапазон дат, покрывающий сегодня — «Средняя
   оценка» показывает 5.0 (1 оценка), взято из реальных данных этого прогона, не из тестовых
   заглушек.
