# Frontend — шаг 6 (регистратор, «я здесь» / «выйти»)

Что реализовано в этом шаге (см. `ARCHITECTURE.md`, разделы 3 Машина состояний, 6 Public/Registrar,
7, 9 шаг 6):

## Бэкенд

- `app/api/registrar.py` (роль `registrar`): `GET /registrar/queues` (открытые/на паузе очереди
  своей организации), `POST /registrar/tickets {queue_id, note?}` — талон без `client_id` через
  `services/tickets.create_ticket(source=registrar, actor_type=user)`, те же проверки очереди, что
  у скана (открыта, расписание, дневной лимит), но без геозоны и без «один активный талон» (нет
  устройства, которое могло бы дублировать). `GET /registrar/tickets/{id}` — статус для
  регистратора. `note` некуда сохранить на самом талоне (в схеме БД такого поля нет и не
  запрашивалось) — он называется/печатается на месте, поэтому живёт только в `audit_logs.payload`.
- `POST /public/tickets/{id}/confirm` — `called -> confirmed` (раздел 3), только владелец по
  cookie `qc`, как везде в `/public/*`. `POST /public/tickets/{id}/leave` — маршрут для уже
  существовавшего `services/tickets.leave()` (waiting/called/confirmed -> `left`, кабинет
  освобождается, если был занят).
- Талон без `client_id` физически не может попасть в `GET /public/me/tickets` (фильтр по
  `client_id == client.id`) и не участвует в rate-limit `/public/scan` — это отдельный маршрут,
  ничего специально исключать не пришлось.
- **Побочная находка и фикс**: вручную гоняя `confirm()` через живой WebSocket, поймал гонку —
  `publish_event` во всех переходах `services/tickets.py` вызывался *до* `db.commit()` в
  роуте-вызывающем, так что подписчик `/ws/operator` иногда успевал перечитать талон раньше, чем
  транзакция становилась видна другим соединениям, и получал старый статус (`called` вместо
  `confirmed`). Для действий оператора это самолечится через `refresh()` после каждого действия
  (шаг 4b), но у `confirm`/`leave` (и у авто-no_show из воркера) такого механизма на стороне
  оператора нет. Поправил: каждая функция-переход в `services/tickets.py`, кроме `create_ticket`
  (она вложена в `transfer()`, комментарий на месте — почему), теперь коммитит перед публикацией
  события. Автотесты подтверждают набор сценариев, воспроизвёл и на реальном сокете (3/3 чистых
  прогона до фикса ловили гонку, после — 0/множество).

## Фронтенд

- `/registrar` (`pages/registrar/RegistrarPage.tsx`, заменил заглушку) — список открытых/на паузе
  очередей, поле «заметка» и кнопка «Записать» на каждую; после создания — номер на весь экран на
  8с («Ваш номер: …, назовите его или покажите на входе»), кнопка «Ещё раз для этой очереди» для
  потока посетителей, затем автовозврат к списку.
- `/t/:id` — кнопки «Я здесь» (только в `called`) и «Выйти из очереди» (waiting/called/confirmed),
  место под них было зарезервировано с шага 3. Confirm/leave сразу показывают ответ сервера
  (`TicketDetailOut`), не дожидаясь WS — тот всё равно вскоре пришлёт то же самое.
- `/operator/queue` — у талона в `confirmed` отдельная зелёная пометка «✓ Посетитель подтвердил
  присутствие» рядом со статусом.
- `AuthContext`/`ProtectedRoute` трогать не пришлось — `roleHome` уже вёл `registrar` на
  `/registrar` с шага 4b, поменялось только то, что там рендерится.
- Строки — новый раздел `registrar` и три ключа в `ticket.actions` на kk/ru/en.

## Ручной сквозной тест

1. Поднять стек, создать организацию/админа/кабинет/оператора — как раньше, плюс пользователя с
   ролью `registrar` (`POST /api/admin/users {..., "role": "registrar"}`).
2. **Регистратор создаёт талон**: войти на `http://localhost:8080/login` регистратором → редирект
   на `/registrar` → выбрать очередь, при желании вписать заметку → «Записать».
3. **Номер показан на экране**: весь экран — «Ваш номер: A-001», подсказка назвать его вслух;
   через 8с (или сразу по «Готово») — назад к списку очередей.
4. **Оператор вызывает его наравне с QR-талонами**: на `/operator/queue` «Вызвать следующего» —
   регистраторский талон берётся по тому же `created_at`-порядку, что и обычные (никакого особого
   приоритета).
5. **Отдельно, «я здесь»**: отсканировать `/q?t=<token>` с телефона (обычный QR-талон, есть
   `client_id`), вызвать его через `/operator/queue`, затем на `/t/:id` этого талона нажать «Я
   здесь» — экран посетителя показывает «Вы подтвердили присутствие, ожидайте приёма», а **на
   `/operator/queue` статус талона меняется на «Подтвердил присутствие» с зелёной пометкой
   мгновенно**, без перезагрузки ни у кого.
